# Feature Specification: 游戏 UI 解析工作流

**Feature ID**: `013-game-ui-analysis`  
**Created**: 2026-09-04  
**Status**: 解析及人工校正预览已交付（2026-09-06）；GPU/局部模型与完整质量验收待实施  
**Input**: User description: "为 .doc/plan/game-ui-analysis-workflow-plan.md 游戏 UI 解析工作流实施主计划制订 spec 文档；使用 Speckit 流程实现。"

本功能让游戏美术、UI 设计者及资产整理者从截图取得可追溯的布局、文字、元素切片和派生图像。用户可以手动指定素材，也可以授权系统检索；补图前可检查具体编辑范围、成本上限和批准内容。

需求来源为 2026-09-04 整合的本地游戏 UI 主计划。本规格完整承接其中 R01—R16 的产品要求；本地实施记录中的文件、草稿和前置运行验收不构成本功能已完成的证据。

交付先提供可用预览，再补齐拆解/补图、批次及正式验收。**首版预览包含手动单图解析、SerpApi/Tavily 双后端搜索及自动切换**：两种输入共用来源、canonical、布局、文字、矩形切片与标注图；搜索不可用不阻断手动入口。工程顺序为先手动、再双后端搜索，不依赖 GPU、父子任务或完整质量评估。

预览以英文横屏 HUD、中文密集 UI、竖屏三个固定开发样本，以及两家各一次有界真实搜索并解析的证据发布；额度切换用固定响应验证，不故意消耗真实余额。完成一次代表性中断恢复、输入/批准/预算及产物硬检查后即可交付，标注“可用预览，完整质量验收待完成”。三例后续纳入开发集，独立评估集不参与调参。

2026-09-06增量：单图预览已经完成，接下来先交付人工校正，再进入拆解/补图、批次和正式验收。用户可直接补框、改框、改字、分类及调整层级，保存可继续使用的布局版本。原始模型结果与历史验收保留；人工确认不等于模型识别准确、素材授权或生成批准。US1—US6、FR-001—055、PER-001—009、SC-001—012及原里程碑编号保持，新增US7、FR-056—067和SC-013—017。

以下 M-U1—M-U3 保留正式验收范围与编号，不再强制实现时间顺序；预览不代表它们全部通过：

| 阶段 | 用户可获得的结果 | 范围 |
|---|---|---|
| M-U1：单图解析 | 来源清单、全分辨率标准图、布局与文字记录、变换说明、矩形切片、标注图 | 手动单图导入、文字识别、视觉理解和布局融合 |
| M-U2：拆解与补图 | 轮廓蒙版、估计透明度的元素图、按需字形图、获批生成结果、质量与批准证据 | 精细分割、去字、场景背景或地图底图补全、局部修订 |
| M-U3：自主检索与批次 | 搜索来源、筛选结果、费用记录、父子任务及完整结果索引 | 有界检索和下载、额度切换、手动及搜索来源的顺序批次 |

术语：OCR 指文字识别；VLM 指能分析图片与文字的模型；canonical 指保留输入分辨率、统一方向后的标准图；mask 指蒙版，其非零区域定义实际允许编辑的像素。`observed` 表示观察所得，`user_declared` 表示用户声明，`hypothesis` 表示推测，`generated` 表示生成内容；这些标签不能相互替代。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 手动指定截图并取得可信布局 (Priority: P1)

用户导入本地截图、HTTPS 图片直链或已获授权的素材引用，先保存输入，再选择分析。用户查看文字、控件关系、原始切片和来源，知道哪些结论有图像证据，哪些仍有不确定性。

**Why this priority**: 手动单图是最直接的使用入口，也是后续拆解和补图的坐标、来源与证据基础。

**Independent Test**: 在没有搜索凭据的环境中导入一张有标注的截图，取得 M-U1 全部产物并比对坐标、文字和引用；导入本身不触发模型分析。

**Acceptance Scenarios**:

1. **Given** 用户指定有效本地截图且搜索能力不可用，**When** 用户只导入素材，**Then** 系统保存不可变输入和来源，搜索、额度探测及模型调用均为零；随后可独立授权分析。
2. **Given** 输入和分析预算有效，**When** 用户执行单图解析，**Then** 返回布局、原始 OCR、文字关联、矩形切片、标注图及来源，所有坐标基于全分辨率标准图，所有引用可解析。
3. **Given** 图片有方向信息、奇数尺寸或经过分块识别，**When** 用户检查切片，**Then** 坐标能还原至标准图，切片与对应原始像素一致。
4. **Given** OCR 低确定性、模型提出文字纠正或交互猜测，**When** 用户查看结果，**Then** 原文、建议、证据和未知项分别保留，建议不覆盖原始观察。
5. **Given** 输入是网页而非图片、已被篡改的引用或未获授权的跨任务引用，**When** 用户导入或分析，**Then** 系统在使用该输入调用模型前拒绝，给出原因，不自动转为搜索。

### User Story 2 - 获取有明确真实性边界的元素资产 (Priority: P2)

系统根据用户目标和布局提出需要拆出的控件或文字，用户检查并批准具体范围，也可修改候选；取得矩形切片、精细轮廓和按需字形资产，并区分实际可见像素与估计透明度。

**Why this priority**: 可解释的拆解资产支持编辑和复用，避免把截图推测误当原始工程图层。

**Independent Test**: 对已有布局和带标注截图执行拆解，检查矩形图、轮廓蒙版、透明度估计和可选字形的角色、尺寸及来源；无需搜索或补图。

**Acceptance Scenarios**:

1. **Given** 一张包含异形控件、半透明面板及遮挡的截图，**When** 用户请求精细拆解，**Then** 每种输出分别标记为原始可见切片、轮廓蒙版或透明度估计，遮挡部分不宣称已还原。
2. **Given** 用户请求文字图像分离，**When** 系统输出字形资产，**Then** 描边、阴影及不确定区域有记录，OCR 矩形框不能代替精细字形蒙版。
3. **Given** 精细分割能力未就绪，**When** 用户请求精细拆解，**Then** 系统报告缺失能力和可用产物，不将矩形切片标为精细分割成功。

### User Story 3 - 检查并批准受限的去字或背景补全 (Priority: P2)

用户明确需要移除 HUD 后的场景背景或地图底图，系统提出区域及保留/移除对象。用户检查预览、最终蒙版和费用上限后批准具体 GPU 子计划；普通流程无需手填选择文件，修订保留历史与实际编辑边界。

**Why this priority**: 补图引入生成成本和推测内容，必须先给用户可审阅的范围与结果边界。

**Independent Test**: 使用固定原图、蒙版和模型配置验证批准拒绝路径；在对应批准就绪后执行一次真实补图，检查编辑区外像素、生成标签和费用证据。

**Acceptance Scenarios**:

1. **Given** 用户明确选择 `scene_background` 或 `map_surface`，**When** 系统准备补图，**Then** 展示原图、保留/移除对象、最终编辑蒙版、生成配置、修订和预算上限，等待与该范围一致的批准。
2. **Given** 缺少批准、输入或蒙版已变、预算不足，**When** 尝试补图，**Then** 实际生成调用为零，并说明停止原因。
3. **Given** 具体批准仍有效，**When** 补图完成，**Then** 最终蒙版为零的每个像素与标准图完全相同，派生结果标为 generated，保留原图和本次批准、成本及质量记录。
4. **Given** 用户修改一个文字框或分割提示，**When** 系统修订，**Then** 只重算受影响结果，保留其他元素身份；最终蒙版变化时原补图批准失效。
5. **Given** 修订次数或逐次/总预算已达上限，**When** 模型建议继续，**Then** 系统有界停止并保留失败尝试，不追加消费。
6. **Given** 布局已完成且目标足够明确，**When** 系统提出具体区域，**Then** 展示预览与待批准子计划，用户一次具体批准同时确认范围与该 GPU 操作，无需先提交选择文件；目标含混时先按候选编号选择，无批准的 GPU 调用为零。
7. **Given** 已受理操作实耗超过预留，**When** 系统结算，**Then** 若仍符合原批准的逐次/总限额，记录预留调整并按重新核算的剩余额度自动继续；若实耗违反批准限额，则如实失败并停止后续提交，不增预算、不清零未知费用。

### User Story 4 - 在共同额度和预算内自动查找截图 (Priority: P1)

用户提供游戏类型或 HUD 场景目标，授权允许的搜索供应商及总范围。系统自动选择有可用额度的供应商，取得真实图片并记录筛选依据、来源和费用。

**Why this priority**: 双后端搜索是首版预览的必需入口，复用单图分析和公共成本控制，不等待分割、补图或批次。

**Independent Test**: 固定搜索及额度响应，验证选路、下载、去重和停止行为；两家供应商的真实可用性另以有界、获授权的网络验证确认。

**Acceptance Scenarios**:

1. **Given** 搜索请求、允许集合和预算已冻结，**When** 系统检索，**Then** 在共享数量上限内自动选路，只把下载校验通过的图片送入分析，记录实际供应商、来源和筛选依据。
2. **Given** 偏好供应商额度低于切换水位、另一家符合条件，**When** 新的安全搜索操作开始，**Then** 系统自动切换并保存原因，不扩大预算，也不重复请求已有集合内的授权。
3. **Given** 两家额度耗尽、余额未知或均不可用，**When** 发起搜索，**Then** 系统有界停止并给出可恢复原因；手动输入仍可使用，不触发搜索额度探测。
4. **Given** 一次搜索可能已受理但没有确定结果，**When** 用户恢复任务，**Then** 系统保留未决费用并对账，不向另一家再次提交同一逻辑查询。
5. **Given** 搜索返回空结果、失效链接、重复图或来源信息缺失，**When** 系统整理候选，**Then** 逐项保留结果与错误，已消耗搜索如实结算，未知来源和使用条件不被补造。

### User Story 5 - 顺序处理多图并保留部分成果 (Priority: P3)

用户明确选择多张图片或检索结果形成批次，逐图查看进度、等待批准、失败原因、总费用和已完成资产。

**Why this priority**: 批次提高整理效率，且必须保留用户选择与父级预算约束。

**Independent Test**: 提交含有效图、无效图、精确及近似重复图的批次，验证逐项映射、同时活动子任务数、共享预算和取消行为。

**Acceptance Scenarios**:

1. **Given** 用户手动选择 2—10 张图，**When** 批次开始，**Then** 不套用搜索默认只选一张的规则；精确重复保留每条来源映射，近似重复只提示，子任务顺序执行。
2. **Given** 一张输入失败且请求的失败策略允许继续，**When** 其余图片完成，**Then** 父任务显示部分完成、逐项原因及已完成结果，不将整个批次标为全部成功。
3. **Given** 子任务等待批准或父级预算耗尽，**When** 用户查看批次，**Then** 能区分等待、停止和完成状态，后续任务不绕过父级约束。
4. **Given** 用户取消父任务，**When** 系统停止处理，**Then** 不启动新子任务，已提交工作可追踪，已完成资产保留，未确认结果及费用保持可见。
5. **Given** 用户选择超过 10 张图，**When** 提交批次，**Then** 系统在启动分析前拒绝，不静默截断。

### User Story 6 - 中断后继续工作并审查证据 (Priority: P1)

用户在进程中断、网络超时或资源不足后，能够查看已完成步骤、继续可安全执行的部分，并理解哪些请求需要对账或重新批准。

**Why this priority**: 首版需要基本恢复和可见的费用/结果；公共副作用边界集中验证，GPU、父子竞争及最终证据随相关能力完成，不将完整恢复矩阵作为单图开工门槛。

**Independent Test**: 在输入登记后、OCR 完成后和外部生成已受理后分别中断，检查恢复用图、外部受理次数、资源归属、历史产物和费用状态。

**Acceptance Scenarios**:

1. **Given** 原始文件在导入后被用户修改，**When** 任务恢复，**Then** 使用已冻结副本，保留旧内容哈希，不重新读取可变源文件或下载地址。
2. **Given** OCR 或素材供给结果已经登记，**When** 进程重启，**Then** 复用已完成结果及身份，不重复搜索、下载或写入同一结果。
3. **Given** 外部生成已受理，**When** 恢复，**Then** 查询原请求或进入结果未知/对账状态，不自动新建生成；资源失联不直接视为空闲。
4. **Given** 视觉服务已持久受理但提交响应丢失，**When** 恢复，**Then** 按预先登记的操作身份只读找回原作业；查无记录不是未执行证明，不增加受理次数。
5. **Given** 用户检查任一资产或失败修订，**When** 查看证据，**Then** 能追到输入、模型/工作流版本、参数、批准和费用，观察、推测与生成内容保持区分。

### User Story 7 - 人工校正解析结果并继续使用 (Priority: P1)

用户打开已解析截图，在原图上的标注、元素列表和属性区之间选择同一个对象，补上漏框，调整边界、类型、文字和层级。用户保存草稿、撤销错误操作，确认一份校正版本后得到更新的布局与切片，后续处理明确使用这份版本。

**Why this priority**: 初步识别会漏检或误分，人工结果必须能成为后续分割和补图的可靠输入；不应为改一个框而重复整图付费识别。

**Independent Test**: 打开已有英文横屏、中文密集及竖屏解析结果，断开搜索和模型服务，完成新增、改框、分类、改字、层级调整、撤销/重做、保存和重开。确认后检查坐标、版本、文字来源和切片，全部新增模型/搜索/GPU调用为零。

**Acceptance Scenarios**:

1. **Given** 解析遗漏图标或框选过大，**When** 用户缩放画布并新增、移动、缩放或删除框，**Then** 标注、列表及属性同步，保存坐标对应全分辨率原图，非法或零面积框不能保存。
2. **Given** 技能按钮同时包含图片和文字，**When** 用户设置容器、子图标与文字，**Then** 允许合理重叠和父子关系，拒绝自引用、循环和悬空关联；无法确认的分类可留未知。
3. **Given** OCR识别错误或漏字，**When** 用户输入修正文或新增文字框，**Then** 原始OCR及模型建议保留，新增文本明确来自人工，不伪造识别分数或模型证据。
4. **Given** 用户已保存草稿或误操作，**When** 关闭重开、撤销/重做或恢复历史版本，**Then** 可恢复内容，历史确认版本及原始识别结果不被覆盖。
5. **Given** 两个页面基于相同版本编辑，**When** 第一个页面保存后第二个保存，**Then** 第二个得到明确冲突及保留其修改的选项，不静默覆盖。
6. **Given** 校正版本通过结构检查，**When** 用户确认，**Then** 仅重建受影响的布局、文字、切片及标注；未变元素身份和像素产物复用，确认既不调用模型，也不批准后续分割或补图。
7. **Given** 元素已人工确认并锁定，**When** 后续局部模型复核返回不同结果，**Then** 作为建议展示，未经用户采纳不覆盖锁定字段；模型调用仍受对应分析预算和次数限制。
8. **Given** 后续计划已绑定某个校正版本，**When** 用户发布新版本，**Then** 旧计划不会自动改用新版本；采用新版本必须重新绑定并取得适用批准，已受理或未知操作保留原输入与费用。

### Edge Cases

- 空输入、manual 与 search 混用、图片网页混淆、未授权引用、输入或元数据版本变化。
- 全部 EXIF 方向、奇数尺寸、超大像素量、重叠分块、边界取整、零面积框、越界框和非法多边形。
- 中英文小字、密集 HUD、遮挡、半透明控件、OCR 无结果、模型虚构字段或无证据的精确断言。
- 原图与蒙版缺一、尺寸或角色不匹配、空蒙版、扩张/羽化扩大实际编辑区域、生成尺寸错误。
- 无搜索密钥、仅一家可用、认证失败、不同额度单位、余额缺失或过期、额度刷新失败、两任务争用最后一份额度。
- 搜索明确拒绝与受理结果未知、空结果仍可能计费、服务器要求更长冷却、月度额度重置、共享凭据变更。
- 带签名的图片链接、重定向到不允许的地址、假图片、压缩炸弹，以及标题、OCR 或用户说明中的越权指令。
- 手动与搜索取得相同内容但来源不同、手动选择近似重复、批次部分失败、等待批准期间取消。
- 已受理生成后进程退出、资源所有者失联、重试次数不清零、证据丢失或哈希不匹配。
- 人工新增文字没有OCR身份、删除父容器但保留子项、改类型后文字关联失效、重叠框与组合控件、锁定字段的批量编辑。
- 不同缩放/像素密度下拖框、多页并发、确认过程中退出、重复提交、存储不足、旧版产物缺失、手动标注误进入模型评估真值。

## Requirements *(mandatory)*

### Functional Requirements

#### 输入、来源与登记

- **FR-001**: 一次请求 MUST 明确选择手动或搜索输入；手动输入持有已登记素材，搜索输入持有非空目标及策略。含混或互相矛盾的组合 MUST 拒绝。
- **FR-002**: 手动入口 MUST 支持本地 PNG/JPEG/WebP、HTTPS 图片直链和已授权既有素材引用，支持 1—10 张明确选择的图片。单图最大 25 MiB，并同时满足已声明像素和资源上限。
- **FR-003**: 系统 MUST 区分图片直链与来源网页。仅作为说明的来源页不被抓取；网页作为图片输入时返回类型错误，不自动搜索。
- **FR-004**: 用户 MUST 能只登记素材而不启动分析。登记 MUST 冻结原始字节及元数据版本；恢复复用冻结副本。导入不自动授权 OCR/VLM、分割或补图。
- **FR-005**: 系统 MUST 校验素材的存在性、哈希及访问范围；跨任务素材经授权后建立当前任务引用及来源关系。输入、蒙版或必要证据被篡改时 MUST 在相关外部调用前拒绝。
- **FR-006**: 每个来源 MUST 有稳定身份、取得方式、时间、原图及来源记录、实测格式/尺寸/哈希。用户标题、游戏名、说明及使用条件标为 user_declared；供应商声明与实际观察分开，未知项保留未知。
- **FR-007**: 手动选择 MUST 跳过搜索排名和默认选图数。精确重复可共用存储及一次分析，但保留每条输入至结果的映射；近似重复只提示，不自动移除。
- **FR-008**: 供给结果 MUST 区分 ready（有素材且无失败）、partial（部分取得）、empty（搜索完成但无可用结果）、unavailable（无可用输入或能力），提供逐项原因；无可用结果不得标为成功解析。
- **FR-009**: 手动与搜索取得的同一内容 MUST 使用相同校验、标准化、坐标和下游分析规则；固定下游响应时布局一致，来源差异仍可追溯。手动入口搜索和额度探测次数 MUST 均为零。

#### 标准图、文字和布局

- **FR-010**: 系统 MUST 保留原始字节，生成应用 EXIF 方向的全分辨率标准图，记录颜色和透明通道处理；最终裁切不得以缩略图替代标准图。
- **FR-011**: 位置 MUST 统一为标准图像素坐标；矩形以左上/右下坐标表达，右下边界不包含，多边形使用同一坐标系。每个分析视图 MUST 保存裁剪、缩放、方向及逆变换。
- **FR-012**: 系统 MUST 在处理前检查字节、像素和分块数量限制，在裁切前拒绝越界、零面积或非法几何；模型给出的坐标未经校验不得驱动产物操作。
- **FR-013**: OCR 结果 MUST 保留原始文本、识别分数、多边形、模型身份和输入视图身份；低确定性及无结果状态不得伪装为准确文本。
- **FR-014**: 局部重读 MUST 指向已登记文字或区域，并计入同一张图的调用上限和预算；纠正建议及依据单独保存，不覆盖原始 OCR。
- **FR-015**: 视觉理解 MUST 区分可观察控件、层级、文本关联、遮挡关系与语义推测；每个推测引用具体元素或文字证据。模型自报置信度不等于已校准准确率。
- **FR-016**: 布局与分析结果 MUST 遵循严格结构合同；非法结构、额外字段、未知动作和超范围修订返回结构化错误，不通过任意执行来修复。无依据的精确交互、字体及自适应布局断言 MUST 拒绝或降为未知/推测。
- **FR-017**: 元素 MUST 使用持久稳定身份；恢复复用身份，修订保留未变元素身份，为新增、删除、拆分和合并记录映射。层级、文字关联和资产引用 MUST 无悬空关系，不能用数组顺序充当长期身份。
- **FR-018**: 单图解析 MUST 提供来源清单、标准图、变换记录、layout.json、texts.json、原始矩形切片及标注图；布局、文字和像素区域能够相互核对。

#### 拆解、补图与修订

- **FR-019**: 拆解 MUST 分别提供原始矩形切片、按框/点提示取得的轮廓蒙版、标为估计的透明度元素图；各产物有独立角色、质量状态及来源。
- **FR-020**: 用户请求字形资产时，系统 MUST 提供独立字形蒙版或图像，处理描边和阴影并标出不确定区域；文字框不得冒充精确字形。
- **FR-021**: 请求的能力缺失或质量未达标时 MUST 明确报告，保留已取得产物，不用低等级产物冒充所请求能力，也不承诺还原遮挡内容或原始图层。
- **FR-022**: 请求 MUST 明确输出模式、语言、局部修订权限和预算；具体拆解/补图前 MUST 形成目标区域及适用的保留/移除对象。默认依据实际布局提出方案并展示预览，用户对具体 GPU 子计划的批准同时确认范围；正常使用不得要求手填选择文件。目标含混时提供候选供选择，专家可覆盖。纯解析不要求编辑选择；未请求或未获具体批准的 GPU 操作不得启动。
- **FR-023**: 补图 MUST 明确 scene_background（去除 HUD 后的场景背景）或 map_surface（地图/小地图底图），在具体计划形成前冻结实际区域。目标类型不能代替区域；提案或覆盖选择绑定有效输入/布局，最终编辑不得超出获批区域或进入明确保留区域；不能仅凭“地图”一词改变编辑对象。
- **FR-024**: 补图 MUST 使用成对且尺寸、角色一致的原图和蒙版，以及声明支持蒙版编辑的已审查工作流；不合格绑定在生成前拒绝。
- **FR-025**: 计划 MUST 明确蒙版极性、通道、缩放、扩张、羽化及其最终实际编辑范围，并把最终蒙版纳入批准指纹。空编辑区域 MUST 不发起付费或 GPU 生成，并报告无待编辑像素。
- **FR-026**: 具体补图批准 MUST 绑定原图、最终蒙版、后端、模型、工作流、有效参数边界、输出数量和全部预算。实质变化须重新批准；仅允许在批准范围内调整提示词、种子及已声明可调参数。
- **FR-027**: 生成图 MUST 先验证尺寸，再只在最终蒙版非零范围合成；最终无损图中蒙版为零的像素 MUST 与标准图逐像素相同。
- **FR-028**: 去字及补全结果 MUST 标为 generated，保留原图、蒙版、失败尝试和每个生成版本。尺寸错误、质量失败或证据缺失 MUST 显示失败原因，不计为成功验收。
- **FR-029**: 局部修订 MUST 限于重读指定文字、调整分割提示、复核指定区域及批准范围内重新生成。上游改变时只重算受影响依赖，复用其余结果；新蒙版不能沿用旧补图批准。

#### 检索、额度与费用

- **FR-030**: 搜索请求 MUST 冻结允许的供应商集合、查询范围、各家请求及计价规则、选图条件、路由策略版本和共同预算。首轮支持 SerpApi 与 Tavily；用户不必手动挑选每次操作的供应商。
- **FR-031**: 查询规划、相关性判断、额度探测、搜索和下载 MUST 分别计数并受明确上限约束；候选分析消耗计入原任务，切换供应商不能增加总配额。
- **FR-032**: 额度 MUST 区分单位、账户及密钥作用域、允许额度池、观测时间、可靠重置时间和信息版本。不同单位按一次请求所需单位折算可执行次数，不能直接比较余额数值。
- **FR-033**: SerpApi 的套餐及额外余额 MUST 分别记录，额外余额不得误称免费赠送；Tavily 可用套餐余额 MUST 同时受明确的密钥限额约束，按量付费池单独记录且默认排除。缺失或异常额度不能解释为零或无限。
- **FR-034**: 额度 MUST 区分 known、stale、unknown；过期且无法刷新时不据此发起搜索。同一账户作用域共享缓存及刷新限制，跨任务、重启不能清空限频记录；每任务每家最多两次外部额度探测，缓存命中不计探测。
- **FR-035**: 可用量 MUST 从有效远端观测中扣除本地在途、未知和未被观测覆盖的消耗，避免重复扣除已覆盖用量。选路、预算检查和额度预留 MUST 作为不可分割的决策，防止并发任务花掉同一份本地可用额度。
- **FR-036**: 选路 MUST 排除未获准、无凭据、认证失效、冷却中、额度未知/过期、不足一次调用或超预算的供应商。仅一家合格时选该家；两家正常时偏好 SerpApi。
- **FR-037**: SerpApi 可用额度比例低于 10%，且 Tavily 比例更高并足够一次调用时，系统 MUST 提前切换；偏好方恢复至 20% 以上才按水位回切。当前方失去资格时可立即转向合格方；缺少可比额度上限时只按绝对可执行次数判断，保留正常偏好。
- **FR-038**: 系统 MUST 区分认证失败、限流、额度耗尽及空结果；遵守供应商更长的等待要求，不将全部限流误判为月度耗尽。两家都不可用时有界停止，给出 quota_exhausted 或 quota_unavailable 等稳定原因，不循环消费、充值或升档。
- **FR-039**: 每次搜索在提交前 MUST 保存实际供应商、额度依据、选路原因、请求身份和尝试序号；同一操作恢复时使用已存决定，不重新按实时余额选路或重置次数。
- **FR-040**: 只有确认原请求未提交或被拒绝后，才可结清其已知消耗并创建新操作切换。超时、服务错误或崩溃不能自动等同于未受理；未知结果 MUST 保留预留并对账，该逻辑查询不得另起替代搜索。
- **FR-041**: 在已批准集合和范围内正常自动切换 MUST 无需重复确认；扩大供应商集合、查询范围、预算或开启新的按量付费消费 MUST 形成新计划及相应授权。
- **FR-042**: 搜索尝试、查询、候选和下载限制 MUST 由两家共享，重试、拒绝后切换和重启均不重置。首轮不自动翻页或升级搜索深度；网页结果数不得当作图片数量保证，竖屏图不得被全局默认过滤掉。
- **FR-043**: 下载 MUST 经过 HTTPS、地址解析、重定向、格式、文件签名、大小、像素及解码检查。只有实际取得且验证通过的图片可进入分析；缩略图不能冒充原图，失效或失败候选逐项记录。
- **FR-044**: 搜索来源 MUST 保留实际供应商、取得时间、内容哈希、实测尺寸、安全来源页、声明信息来源及已知使用条件。未知来源关联或许可不得推断补全，供应商描述不替代截图证据。
- **FR-045**: 搜索候选 MUST 经过精确和可配置近似去重，并按游戏类型、HUD 场景及清晰度筛选；筛选理由、被排除项和实际分析用量可查。去重不得覆盖其他手动或搜索来源关系。
- **FR-046**: 免费额度仍 MUST 计入请求单位；美元成本、免费或零费用结论须有计价依据。空结果和被拒绝尝试按实际规则结算，未知费用不得记为零。
- **FR-047**: 套餐重置 MUST 仅更新额度观测，不清空任务费用、未决操作或预留；重置时间不可靠时保持未知，不推断为本地月初。
- **FR-048**: 凭据变更 MUST 使相关健康及额度缓存失效，但不改写既有操作身份或供应商。额度持久记录只保存必要白名单字段及无秘密的作用域标识，不保存完整账户响应。

#### 批次、恢复与任务查看

- **FR-049**: 两种来源的批次 MUST 使用同一单图流程，最多 10 张，同时活动子任务最多一个；所有子任务共享父级预算和已消费次数，同一任务的能力调用顺序执行。
- **FR-050**: 批次 MUST 明确失败策略，默认保留成功结果、逐项报告输入失败并继续可独立执行的输入；具体选择、预算、批准及结果未知等门槛不得被此策略绕过。父任务展示完成、失败、等待批准及未处理项，不将部分结果标为全部成功。
- **FR-051**: 父任务取消 MUST 停止新子任务和新外部提交，对已提交工作保留身份、取消或对账状态、成本及产物，不产生无归属后台生成。
- **FR-052**: 恢复 MUST 复用已登记的输入、来源、分析结果和操作身份；修订写入新版本，历史不被覆盖，不重复写入同一完成结果或重新搜索/下载已登记素材。
- **FR-053**: 每一步 MUST 保存输入身份及哈希、能力版本、参数和产物依赖，以支持只重算受影响部分；不可验证的结果不作为有效缓存继续使用。
- **FR-054**: 外部操作可能已受理时 MUST 查询原请求或进入结果未知/对账状态，保留费用和资源归属。进程或资源报告失联不得直接判定设备空闲，也不得自动重发生成。
- **FR-055**: 用户 MUST 能通过命令行登记、规划、检查区域提案和产物、批准执行、按候选编号调整选择，以及修订、恢复和取消 UI 任务。任务显示阶段、适用的父子关系、停止原因、剩余限制和未确认费用；文件选择作为高级覆盖方式，普通路径不要求手填 hash、来源或布局引用。

#### 人工校正与版本确认

- **FR-056**: 用户 MUST 能在本地可视化页面打开有完整可验证解析产物的单图，联动查看原图标注、元素列表及属性；支持缩放、平移、选取、新增/移动/缩放/删除矩形框、显示/隐藏标注。正常操作不要求填写坐标文件、哈希或素材引用。
- **FR-057**: 人工标注 MUST 区分基础类型（文字、图像、容器、其他/未知）与可选语义标签（图标、角色立绘、插画、背景、按钮、面板、地图、进度条等）。基础类型影响处理，标签描述用途，不自动触发操作。Live2D、原画工程或制作方式仅作有来源的声明/未知，不能凭单帧断言。
- **FR-058**: 用户 MUST 能编辑父子关系、文字关联及锁定状态，允许合理重叠，拒绝越界/空框、自引用、循环和悬空引用。删除带子项的容器须明确保留子项并解除父关系或一并删除；拆分/合并的身份关系必须可追溯，首版可通过显式新增/删除/重设父级完成，不要求自动拆分算法。
- **FR-059**: 用户 MUST 能修正文本和新增文字框；原始OCR文本、分数、范围和模型建议不可覆盖，人工文本分别记录来源及适用版本。修改几何不伪称模型重新识别，文字框及修正文不等于字形素材。
- **FR-060**: 每次保存 MUST 绑定原图、基础布局和草稿版本，记录操作者来源、修改动作及版本关系；支持撤销/重做和重开已保存草稿。确认版本不可变；恢复历史内容产生新草稿，不能删除历史或改写原任务终态。过期基础版本和重复请求不得造成覆盖或重复版本。
- **FR-061**: 草稿保存和确认 MUST 分开。确认须验证并完整生成有效布局、文字投影、矩形切片、标注图及manifest后再发布；失败或中断时原确认版本仍有效。只重算受影响产物，未变元素身份/内容保持，明确显示哪些内容已人工确认。
- **FR-062**: 纯人工编辑、撤销、保存和确认 MUST 不调用搜索/OCR/VLM/GPU，不消耗模型调用或补图修订次数，也不生成批准回执；仍受本地存储与输入大小限制。需要模型重读/复核时必须显式选择目标，按现有分析授权、共同预算及次数准入，不借保存或换版本重置额度。
- **FR-063**: 后续模型结果 MUST 不静默覆盖人工修改或锁定字段，建议与有效内容分开；采纳建议是显式人工修改。后续分割、补图和局部修订 MUST 绑定明确的布局版本与哈希，不能运行时读取可变“最新版本”，确认布局不能替代生成批准。
- **FR-064**: 编辑入口 MUST 限定本地操作者、本任务及获授权产物，阻止其他网页跨来源写入、未授权素材读取与任意路径操作。文字和标签作为不可信资料显示，不能变成脚本、工具权限或执行指令；凭据不进入页面持久存储、公开日志和产物。
- **FR-065**: 校正状态 MUST 与原解析任务状态独立；缺原图、布局或有效引用时明确拒绝或只读展示原因，不重新运行原任务来补造结果。新版可读取历史解析产物但不改历史指纹；旧读取端对不支持的校正版结构明确拒绝。
- **FR-066**: 正式质量报告 MUST 区分自动解析结果、人工辅助结果和独立评估标注；不得用本次人工修改后的结果替换自动识别分数或直接当独立真值。人工确认仅表达操作选择，不证明语义完备或生产可用。
- **FR-067**: 第一阶段 MUST 提供单图、单本地操作者的矩形校正闭环，支持至少512元素、4096文字记录及最近100步未保存操作撤销/重做；超出配置上限时明确拒绝并保留草稿。像素级蒙版编辑、Live2D工程解析、多人实时协作、云端部署及新增模型复核按钮留待相应后续阶段，不纳入人工校正首版。

#### 数量和路由默认值

以下取主计划建议值作为首轮规格默认值；在计划中记录有效配置和更严格的用户限制。它们不代表免费额度，也不替代请求必填的美元和 GPU 分钟预算。

| 项目 | 首轮默认值或边界 |
|---|---|
| 手动输入和批次数量 | 1—10 张；10 张为首轮硬上限 |
| 单图文件大小 | 最大 25 MiB；另受像素、内存和磁盘预算限制 |
| 查询 / 外部搜索尝试 / 供应商切换 | 每任务最多 3 / 3 / 2 次，两家共享 |
| 候选 / 下载 / 默认选图 | 每逻辑查询最多20候选、5下载、默认选1张；搜索根选图上限默认1、可明确设置至10，不保证取得该数量；切换不重置累计数 |
| 单图 VLM / 局部 OCR 重读 | 最多 4 / 2 次；全图、局部、筛选等实际调用均须归属并计数 |
| 补图修订 | 每图首次生成后最多2次，根预算的共同修订上限默认2、可收紧；所有子计划及修订共享，换mask/子计划不清零 |
| 批次执行 | 同时活动子任务最多 1 个 |
| 额度刷新最短间隔 / 有效期 | 同一作用域 75 / 300 秒；过期不可作调用依据 |
| 外部额度探测 | 每任务每家最多 2 次；Tavily 同一作用域每 10 分钟最多 10 次，重启不清零 |
| 默认冷却 / 本地退避上限 | 60 / 600 秒；供应商要求更长等待时遵守更长值 |
| 低水位切换 / 回切 | 低于 10% / 恢复至 20% 以上 |
| 按量付费池 | 默认不纳入；扩大消费须重新授权 |

### Policy and Evidence Requirements *(mandatory for model, data, or workflow features)*

- **PER-001**: 每个模型、适配能力及供应商 MUST 有明确许可/条款身份和 production、conditional 或 restricted 通道；条款未知时拒绝模型使用，conditional 需本地人工确认，restricted 仅限隔离研究并阻止派生物生产导出。截图的未知使用条件须保留，用户说明和搜索发现不自动授予生产许可。生产导出仍需完整来源、质量和许可检查及人工批准，不成为 Agent 工具。
- **PER-002**: 计划 MUST 声明磁盘、内存、显存、网络、运行时间、逐次/总金额、GPU 分钟、调用次数和修订预算，不支持无限预算。资源基线为 Windows 11、单张 10 GiB 显存 RTX 3080 和 64 GiB 内存；能力未就绪或资源不足时明确停止，不静默降规格、不终止无关进程。本功能仅处理静态图片。
- **PER-003**: 分析授权 MUST 限定输入、检索及 OCR/VLM 等能力、派生写入和预算；规划仅可消耗明确预留的规划预算。付费媒体及 GPU 操作必须有与具体输入和范围相符的精确批准指纹；分析授权不能替代补图批准，也不能重用已耗用的历史 GPU 批准。
- **PER-004**: 所有分析、生成、修订及评估 MUST 保存代码和运行版本、模型身份/快照及可用哈希、工作流/配置哈希、原始输入和视图哈希、提示版本、种子、有效参数、硬件/软件身份、批准、预留与实际用量、输出哈希及派生关系。失败和未决记录同样可查，不以终态成功替代外部受理次数和账目证据。
- **PER-005**: 原始截图、用户说明和受限来源 MUST 保持任务作用域内的访问与留存边界；拥有分发权的合成样本可入版本管理，私有和受限截图仅本地保存及记录哈希。缓存与输入、批准、会话和运行证据必须区分，恢复所需记录不得当作可丢缓存。可移交结果使用相对资源引用，不含绝对路径、秘密或模型权重。
- **PER-006**: 图片内容、OCR、网页标题、供应商描述、文件名和用户说明 MUST 视为不可信资料，不能增加权限。受控入口之外不开放任意文件读写、shell、模型下载、训练、批准或生产导出。凭据、认证头、原始 URL 查询/片段、绝对输入路径及未脱敏异常不得进入日志、任务历史、manifest 或可移交结果；原始标题、文字、用户说明及逐项错误通过受限素材引用传递，不把正文或原始供应商响应带入日志和任务历史。
- **PER-007**: 本项 MUST 复用已验收的任务、素材、批准、成本及资源管理规则，保持现有图片、Sprite、短剧和专家入口兼容，不扩大旧输入入口数量限制。运行服务仅本地监听，能力及工作流保持受审查的原生白名单；新视觉能力不得破坏现有可用生成环境。能力、结构合同和质量检查必须有版本且可关联输出。
- **PER-008**: 正式完整验收 MUST 使用至少24例，其中至少8例为已知背景加合成HUD，覆盖中英文小字、多分辨率、密集HUD、异形、半透明及遮挡。预览先固定三个开发样本，随后补齐开发16/评估8，已知背景按4/4分布，底图来源不跨集合。度量和标注在使用对应集合前确定；质量阈值在开发集实测后、独立评估前冻结，不看评估结果降低门槛。预览不因完整样本/阈值尚未齐备而阻塞，但不得声称正式质量通过。
- **PER-009**: 验收 MUST 分开记录离线合同、真实OCR、VLM、分割、补图、两家搜索及端到端证据；缺真实记录的能力保持未验收。付费/网络/GPU验证须明确开启且符合具体授权及预算，不自动部署模型。公共执行不变量集中验证，适配器只验证自身边界；最终复用仍有效的已有证据并只补缺口。普通本地任务不要求不适用的批准/受理次数/费用字段，前置或替身记录不能替代真实能力记录。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 正式验收在至少 24 个冻结案例及规定的可用环境中，所有 M-U1 必需产物齐全，100% 通过结构、输入哈希、几何及引用完整性硬检查；结果能由标注图与切片逐项核对。
- **SC-002**: 无搜索凭据、两家额度耗尽及额度探测超时三种场景下，所有有效手动输入均可完成已授权的单图路径，搜索和额度探测调用次数均为 0。
- **SC-003**: 同一内容分别从手动和搜索取得时，标准图像素与坐标一致；固定下游响应的对照验证中布局一致，全部输入来源映射保留。
- **SC-004**: 正式验收的独立评估集的文字错误率、定位及分割重叠度、文本关联、场景语义和接缝质量均达到预先冻结的对应门槛；每项提供测量值、分母、适用样本和阈值版本。至少 8 个已知背景案例提供补图真值比较，无真值截图只报告可观察合理性。
- **SC-005**: 每个实际补图结果在最终蒙版为零的区域像素差为 0；全部补图和去字结果标为生成，全部透明度估计及语义推测具有对应标签和来源。
- **SC-006**: 无批准、过期批准、输入/区域/蒙版篡改、未授权引用及超预算准入拒绝时，被阻止能力的外部调用次数为0。实耗超过预留但仍符合原批准逐次/总限额时，如实记录预留调整；重新检查后续预留仍可容纳则自动继续，否则停止新增消费并保留成果。实耗违反批准限额时任务失败、发现后新提交数为0；未知费用不清零，不提高批准预算。
- **SC-007**: 额度选择验证覆盖单一可用供应商、低水位切换、回切、两家耗尽、过期/未知余额和冷却；所有决定符合冻结规则，两个任务争用最后一份本地额度时最多一个获得预留。
- **SC-008**: 在输入登记后、OCR 完成后及外部受理后中断的全部恢复用例中，已完成结果身份不变，已受理操作无重复提交，未确认费用不归零，未知结果不触发替代调用。
- **SC-009**: 包含 10 个输入的混合批次中，同时活动子任务不超过 1，100% 输入有结果或明确失败/等待映射；第 11 个输入在启动分析前被拒绝。取消后无新子任务，已提交工作全部有归属。
- **SC-010**: 局部修改验证中，未受影响元素的身份及产物哈希保持不变，受影响元素有修订映射；所有改变最终蒙版的修订均使原补图批准失效。
- **SC-011**: 注入合成秘密、URL 参数、绝对输入路径和越权标题的全部检查中，日志、错误链、任务历史及移交结果中禁止信息命中数为 0，越权动作执行数为 0。
- **SC-012**: M-U1、M-U2、M-U3 各有可核验的产物和真实能力记录；全部产物可追到来源、版本、批准与费用。三阶段及完整回归全部通过才宣布完整交付，任何未验证能力均明确列出。

- **SC-013**: 三个既有开发样本各完成至少一次新增、改框、改字、分类及父级调整，累计覆盖删除、锁定、撤销/重做、保存重开和不修改直接确认；100%确认版本可核对原图、修改来源、有效文字、布局和切片，新增搜索/模型/GPU调用均为0。
- **SC-014**: 在25%、100%、200%显示比例及不同显示像素密度的固定操作用例中，保存区域与标准图坐标相符，全部切片逐像素匹配；未改元素ID保持率100%，同范围切片内容哈希复用率100%。
- **SC-015**: 并发保存、重复提交、确认中断及存储不足用例中，已确认版本被静默覆盖次数为0，冲突修改可恢复；每个幂等请求最多发布一个版本，失败确认不会替换原有效版本。
- **SC-016**: 跨来源写入、无效会话、越权素材及恶意文本测试中，未授权写入/执行为0；所有纯人工动作新增模型请求及批准回执为0，旧根预算和未决费用保持不变。
- **SC-017**: 冻结版本依赖、锁定字段复核与评估来源测试中，未采纳模型建议对人工有效内容的覆盖次数为0；版本不符的下游操作在外部提交前全部拒绝，自动/人工辅助/独立真值来源100%可区分。

## Assumptions

- 人工校正先作用于已完成且产物可验证的解析任务；原图保持不变，换图需重新导入。用户可以直接确认未修改的初步布局，不要求每个框逐一打勾。
- 首版人工校正可离线完成；模型辅助局部重读/复核由后续局部修订阶段接线。标签不是拆解/删除意图，确认不是付费批准。
- 人工校正草稿与模型生成修订分别计数；旧记录、旧预算及历史失败保持可追溯。正式质量仍使用独立冻结评估标注。

- Draft 不批准付费或GPU操作。用户已在计划讨论中确定双后端首版、自动提案及预留调整自动继续；本次修订后只运行一次只读Analyze并汇报，不自动修订或循环复核。
- 首轮面向本地单机使用者，以命令行提供操作；新的 Web 上传应用、原始 UI 工程重建、精确字体识别、交互行为证明、响应式布局还原、训练和生产级高可用部署不在范围内。
- 从一张截图无法保证恢复隐藏背景、原始 alpha 或原始控件图层。场景背景与地图底图是两种明确目标，默认不互相代替。
- 手动 HTTPS 输入仍需网络，但不依赖搜索；本地手动导入可独立使用，后续模型分析需要其自身能力、凭据和预算。
- 使用现有已验收的持久任务运行基础及批准、素材、成本和资源规则。前置依据可查阅 [运行说明](../../docs/temporal-runtime.md) 与 [验收记录](../../docs/temporal-validation.md)，前置历史批准不覆盖本项调用。
- 主计划给出的调用和路由建议值在本规格中采用为首轮默认值；像素、分块、时长等资源配置在后续计划冻结，执行前必须明确且满足 PER-002，不推断为无限。
- 空蒙版采用无生成的明确停止；批次普通输入失败默认保留部分成果并继续独立输入。这两项是在原计划边界内选择的可验证默认行为，可在 Clarify 阶段调整。
- 不预先编造OCR或分割精度。代表样本与硬检查仅支撑可用预览；各能力随后在开发集建立基线、冻结阈值并独立评估，未冻结门槛不得宣布正式质量验收通过。
- 搜索账户的远端消费可能同时来自其他程序。额度观测并非供应商预留，本功能保证本地共同预算和预留规则，不承诺通过轮询消除所有账户并发扣费；不自动修改账户充值或按量付费设置。
- 原技术选型和历史证据保留；G00—G12旧依赖仅作历史映射，不强制新交付顺序。新Tasks按实际接口/数据依赖开工，草稿先核对复用；文档、包安装或文件存在不解除对应运行验收。
